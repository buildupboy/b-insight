# 분석 입력의 개인정보 보호

자연어 분석 전에 브라우저와 서버가 동일한 규칙으로 민감정보 패턴을 검사한다. 감지되면 원문을 마스킹해서 재사용하지 않고 요청 전체를 거절한다. 화면에는 원문을 포함하지 않은 고정 안내만 표시하며, 서버는 HTTP 422를 반환한다.

브라우저에서 차단한 입력은 분석 API에 보내지 않는다. API를 직접 호출한 경우에도 서버가 DB 조회와 외부 LLM 호출 전에 차단한다. 외부 LLM을 직접 사용하는 `parseConditions`와 내부 분석 함수에서도 동일하게 검사한다. 조건 수정의 업종·지역과 추가 선택값도 검사한다.

탐지 대상은 이메일, 국내 전화번호 및 +82 표기, 주민등록번호 형태, 긴 숫자 식별자(계좌·카드 등), 비밀번호·API 키·인증번호 등의 명시적 표기, 이름의 명시적 소개, 도로명 상세 주소 및 일부 지번·건강정보 표현이다. 전각 문자와 일부 보이지 않는 문자를 정규화한 뒤 검사한다. 긴 숫자는 보수적으로 차단하므로 숫자로만 쓴 큰 예산은 차단될 수 있다. 이때 ‘10억원’처럼 단위를 사용한다.

분석 요청 본문 및 원문을 파일·DB·로그에 영구 저장하는 코드는 추가하지 않는다. 기존 분석 로그도 상태 코드와 숫자 시간 정보만 기록한다. 분석 응답에는 `Cache-Control: no-store`를 적용한다. LLM 응답에 민감정보 패턴이 있으면 오류의 추출 조건에 포함하지 않는다. 외부 LLM 요청에는 `store: false`를 지정한다. 이 옵션만으로 외부 제공자의 모든 보관 정책이 해제되는 것은 아니다.

## 보장 범위와 제한

규칙 기반 탐지는 모든 민감정보를 식별하지 못한다. 이름만 단독으로 쓴 경우, 우회 표기, 문맥으로만 드러나는 건강·재산·사생활 정보는 놓칠 수 있다. 따라서 **‘어떤 민감정보 원문도 외부 LLM에 전송하지 않는다’는 절대적인 보장을 이 구현만으로 선언할 수 없다.** 감지되지 않은 자연어는 기존처럼 외부 LLM에 전달된다.

절대적인 원문 미전송이 필수라면 자연어의 외부 LLM 전송을 중단하고 로컬 모델/로컬 파서로 처리해야 한다. 기존 ‘조건 선택’ 방식은 분석 조건 해석을 위해 외부 LLM을 호출하지 않는 대안이다. 지역명 해석을 위한 외부 지오코더는 별도 경로이므로 ‘조건 선택’이 모든 외부 통신을 제거한다는 의미는 아니다.

서버가 직접 받은 본문은 검사하는 동안 메모리에 존재한다. 여기서 미저장은 파일·DB·로그 등에 영구 보관하지 않는다는 뜻이다. 프록시·호스팅·APM·네트워크 계층의 본문 수집 설정과 이미 저장된 과거 기록은 이 변경에서 검증하거나 삭제하지 않았다. 로그인/회원가입 자격증명 처리는 분석 원문과 별도 기능이다.

## 검증

`node --test backend/input-privacy.test.js`

합성 데이터로 민감 입력 차단, 외부 호출 0회, DB 조회 전 차단, 고정 오류 응답, 운영 모드의 로그 필드, 정상 업종·지역·예산 통과, LLM의 저장 옵션과 응답 민감정보 비반영을 확인한다. 테스트는 실제 개인정보나 외부 LLM을 사용하지 않는다.
