# 행정동 창업 추천 계산

자연어에서 OpenAI가 업종, 지역, 기간과 선호를 추출한다. 서버는 소진공 상권 목록의 검증된 시군구와 상권명으로 지역을 식별한다. 관련 상권의 `adongCd` 또는 상권 내 점포의 `adongCd`, `adongNm`으로 행정동 후보를 확인한다. 8자리·10자리 코드를 수용한다. 후보가 둘 미만이면 같은 시군구 점포 첫 페이지, 이어서 공식 `/baroApi` 행정경계 목록에서 행정동을 찾는다. 상권명은 후보 탐색에만 사용하며 결과는 `구 동`과 행정동 코드 단위다. 후보 탐색은 관련 상권 10곳, 확인된 행정동 12곳으로 제한되며 제한을 화면에 표시한다.

각 행정동은 `/storeListInDong`을 전체 및 검증된 업종 코드 필터로 따로 조회한다. 점포 `bizesId`를 중복 제거하고 양쪽 조회의 기준월, 행정동 코드가 존재하면 일치 여부, ID 포함 관계 및 페이지 완전성을 확인한다. 페이지당 최대 1000개를 요청하고 제공처가 적게 반환하더라도 `totalCount`에 도달할 때까지 다음 페이지를 조회한다. 완전하지 않으면 점포 수와 비교 점수를 결측 처리한다. 소분류와 대분류는 섞지 않는다.

## 점수

- **적합도 30%**: 비교 대상 행정동의 전체 점포 수를 상업 활동의 제한적인 대리 지표로 사용한다. 소비 수요, 임대료, 매출로 해석하지 않는다.
- **경쟁 25%**: 동일 업종 점포 수 / 전체 점포 수를 역방향 정규화한다. 전체 점포가 0이면 결측이다.
- **안정성 25%**: 부산 변화지표의 `comm_nm`은 행정동 코드가 아니다. 검증된 행정동 연결 지표가 없으므로 점수는 결측이다. 이름이 시 전체에서 유일하게 일치한 상권의 `average_open_months`만 같은 구의 단순 평균으로 계산해 카드에 **구내 상권 참고값**이라고 표시한다. 동별 생존기간이나 안정성 점수로 사용하지 않는다.
- **성장성 20%**: 부산 이력의 주소·업종 분류가 소진공 행정동·업종 코드와 정확히 연결된 경우에만 개폐업 사건을 사용한다. 현재 제공처의 응답 업종 필드와 대응표를 실제로 검증하지 못해 결측이다.

값이 두 개 이상인 비교 지표만 5·95 백분위에서 자른 뒤 0~100으로 정규화한다. 한 후보뿐이거나 값이 같으면 비교 점수를 만들지 않는다. 유효 지표 2개 이상이면 가중치를 재정규화해 점수를 계산하고 상위 3개만 표시한다. 따라서 현재 점수는 **전체 점포 규모와 동일 업종 비중으로 비교할 수 있는 행정동이 둘 이상 있을 때만** 나온다. 안정성·성장성 결측을 0이나 추정 수치로 채우지 않는다.

후보별 원값, 실제 가중치, 기준월과 누락 이유를 화면에 제공한다. 지도·관심 저장은 검증된 위치 및 저장 기능이 없어 비활성이다.

## 검증 한계

공공 API 도메인은 현재 실행 환경에서 연결이 실패했다. 실제 서비스의 행정동 코드 포함 여부, 업종 필드, 날짜 필터 동작과 최신 기준월은 확인되지 않았다. 모의 응답을 사용한 통합 테스트는 8자리 행정동 코드, 주변 상권의 동 정보가 비어 있는 경우, 같은 구와 공식 행정경계로 확장하는 경우, 두 자연어 예시의 점수와 상위 3개 제한을 확인한다. 실제 제공처 데이터가 범위를 완전히 제공하지 않으면 점수 대신 데이터 부족이 표시된다.
